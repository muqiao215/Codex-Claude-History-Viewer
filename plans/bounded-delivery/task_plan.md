# History 独立、有界交付

Status: **完整交付执行中（2026-09-15）**。用户明确授权“一次性完成完整交付计划”，覆盖剩余 H0/H1/H2/H4/H5；此前单卡完成即退出限制由本次授权取代。保留冻结退出条件与证据标准，不用 Goal/cron，不把未运行平台记为通过。

复用现有 `history_core` parser/indexer 和 headless CLI，让 Agent 在没有网页、CM 或模型调用的环境中检索指定历史证据，并输出带来源与基线的上下文候选；让人先看到项目进展、成果、阻塞、待决定事项、下一步及对应证据。History 自行验收和发布。

History 保留显示/复制显式原生 resume command 的能力，用户可选择原生 CLI 直接执行，也可选择 CM 做受监督接管；TaskHub 不构成前置条件。History 自身不执行 provider 会话。任务授权、所有权和多设备协调，以及经 CM 的原生续接由 CM 负责。History 的 native-reference 只给上下文候选；CM 实际运行不是本项目独立交付的硬依赖。CM 当前任务事实是可选适配，未连接时明确 unknown；SpecMesh 项目文件仍是审查后的项目事实，不建立第二份决定数据库。Ops 不在本计划范围内。

## HV-H1 性能验收约定

以下是**待测目标，不是已测成绩**。选择 HV-H1 时先提交一次基线结果；若固定数据/机器不适用，先公开修改目标版本，不能看见失败后静默放宽。

- 固定种子合成 JSONL 数据集：1k/10k 会话，每会话 20 条消息、约 16 KiB（允许 ±10%，记录精确字节数）、中文/Unicode、长行、坏尾行和同时间戳样本；登记生成器版本、数据摘要、机器 CPU/RAM/磁盘、OS/Python、源码 HEAD，禁止扫描全量私人历史代替基准。
- 初始索引：1k ≤ 10 s，10k ≤ 90 s；10k 峰值 RSS ≤ 512 MiB。分别记录派生缓存全新和复用状态，不称为操作系统冷缓存，除非确实控制了缓存条件。
- 单文件追加 1 KiB：1k ≤ 2 s，10k ≤ 5 s；解析计数只增加受影响文件，不重解析未变文件。删除/替换后最多一次显式 refresh 得到正确结果或显式错误，不能继续称 fresh。
- 10k 索引上固定 100 次查询（含无匹配、中文、同时间戳和跨页，limit≤100）：热查询 p95 ≤ 250 ms，首次进程查询 ≤ 1 s；分页无重复/漏项的条件绑定同一索引修订，变化时显式失效或重查。
- CLI 退出后无残留子进程、线程或后台 I/O。首版不新增 daemon；按需 `refresh` 已能满足独立调用。只有实测需求证明需要常驻模式时才另选有界子卡：空闲 60 s 平均 CPU≤单核 1%、RSS≤256 MiB、无来源变化时源内容读写 0、派生写入 0，待处理文件数/字节数须有限额并在超限时报告 backlog，不能无限积压。

这些数字只属于上述合成数据集和登记环境，不推广为所有 provider、硬件或长日志的性能承诺。首张卡不跑这组规模测试。
